                          Zram And Zswap Options
                             
  DESCRIPTION:
  This dialog provides two options for compressed swap usage, along with
  a separate swap cache flush button if needed.

  On opening, the dialog will show if an option is currently active. Any
  selections made are immediately enabled and any option change survives
  reboot. Overall, the dialog should be fairly straightforward.

  Zram is a compressed block device that sits in RAM working alongside
  your existing swap. Those without a dedicated swap partition may
  benefit most from using Zram.

  Zswap is a compressed cache that sits in front of your actual swap,
  intercepting and compressing pages that are then held in RAM until
  needed. Zswap is generally a safe choice for most setups.

  Do you need either one? No, but giving them a go shouldn't be an issue
  either way. Several distributions enable Zswap by default, and a few
  even have Zram as default.

  Zram and Zswap shouldn't be used together. This dialog won't allow it
  as a choice anyway, so no worries there.

  For Zswap, you need to have a swap partition or file available. The
  dialog will still allow enabling of zswap whether you have one or not.
  If you add a swap partition later, zswap will already be enabled.

  Check to see if you have a swap partition with:
  swapon --show

  AFTER SELECTION:
  # Zswap confirmation:
  cat /sys/module/zswap/parameters/enabled
  cat /sys/module/zswap/parameters/compressor

  # Zram confirmation:
  zramctl
  swapon --show
  lsmod | grep zram

  Enabling Zram will also change four sysctl values for improved overall
  performance.

  # To see the sysctl values after enabling/disabling Zram:
  sysctl vm.swappiness vm.watermark_boost_factor vm.watermark_scale_factor vm.page-cluster

  Active:
  vm.swappiness = 160
  vm.watermark_boost_factor = 0
  vm.watermark_scale_factor = 100
  vm.page-cluster = 0

  Disabled (standard kernel defaults restored):
  vm.swappiness = 60
  vm.watermark_boost_factor = 15000
  vm.watermark_scale_factor = 10
  vm.page-cluster = 3

  These values can be changed within the script if desired. See:
  /usr/local/bin/zram-zswap-toggle - lines 169 and 192.

  The cache flush button forces the swapped pages back into RAM and then
  reloads swap. There is a small chance this could hang or fail if there
  isn't enough RAM to hold everything currently in swap. The system will
  also still release cached pages as needed without intervention.
